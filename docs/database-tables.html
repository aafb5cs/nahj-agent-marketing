Nahj Seller Marketplace · database design for review · 25 Oct 2026

31 tables for the marketplace, and the changes to the game database

The marketplace gets its own schema nahj_market on the same Cloud SQL server. The game schema nahj only gets new columns on orders, one outbox table and new account attribute keys. Each card lists the columns, types and keys; "Show SQL" gives a draft CREATE TABLE. Optimized on 25 Oct 2026 from a first draft of 73 tables: concepts that were separate tables are now columns, JSON values or rows in shared tables.

Conventions
  • MySQL 8, InnoDB, utf8mb4. Every column is NOT NULL unless marked NULL.
  • Money is BIGINT whole rupiah. Rates are basis points (INT, 1000 = 10.00%). Times are DATETIME(3) in UTC.
  • Statuses are short VARCHAR values checked in code. Rows people edit carry version for stale-edit checks.
  • "Only one active" rules use a nullable flag (1 or NULL) inside a unique key.
  • FK marks a reference to another table. The draft SQL leaves foreign-key constraints out; migrations decide which ones to enforce.
  • The marketplace never connects to nahj; the game backend never connects to nahj_market. They talk through internal APIs.
