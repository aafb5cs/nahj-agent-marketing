The six journeys as flowcharts

Each chart follows one journey through the people and systems involved, with every decision point and its branches. Rules and story IDs sit beside each chart. Decisions are as recorded on 24 Oct 2026.

Flow 1

Purchase, from sale link to VIP or codes

Lanes show who acts. Fulfillment happens inside payment acceptance, with no seller step and no 30-minute window.

Rules

  • Quantity above 1 always means codes; direct is quantity 1 only.
  • Previewing a link never claims it.
  • A late success on an expired attempt is still accepted at the original price.
  • Redirects and screenshots are never proof of payment.
  • New VIP days start at the end of the buyer's current VIP time.

Flow 2

Redeem a code, on the web or in Android

Checking a code reserves nothing. Only Confirm consumes it, inside one locked transaction.

Rules

  • A code's days start at redemption, not at payment.
  • A unit reserved for refund cannot be redeemed.
  • Redeem is rate-limited per account and per code, not only per IP.
  • A push notification is a refresh hint, never the grant.

REC-01 · REC-02 · REC-03 · T09 · T23 · T24

Flow 3

Refund, per unit

A request changes nothing. Finance chooses the units, and each unit is checked against its own window.

Rules

  • Windows are settings: 48 h after activation, 30 days for unused codes. Each order keeps the values from its purchase.
  • Chargebacks cannot be refused; they use the same unused-days rule.
  • A surplus-payment refund touches no grant and no seller balance.
  • The seller cannot approve or block a refund.

CUS-08 · FIN-02 · FIN-04 · T12 · T13

Flow 4

Commission and withdrawal

Money moves between the seller's ledger buckets: Pending, Held, Available, Locked. Withdrawn is the running total paid out.

Rules

  • Commission = unit price × the seller's rate; a seller override wins over the default.
  • Pending never covers debt early.
  • A destination change notifies the old email and pauses withdrawals for a while.
  • A higher provider fee never silently lowers the confirmed net.

SEL-07 · SEL-08 · FIN-03 · SYS-03 · T15 · T16 · T17

Flow 5

Seller onboarding and status

Approval starts onboarding. Selling starts only when the checklist is complete.

Rules

  • Display names are unique and cannot look official.
  • Profile edits are reviewed; the approved version stays live meanwhile.
  • Withdrawal holds need a Finance capability.

SEL-01 · SEL-02 · SEL-03 · SEL-11 · SM-01 · SM-02 · SM-03 · T20

Flow 6

App purchase with an agent code

A second sales channel. The user pays Google or Apple inside the Nahj app; the agent code saved on the account credits the agent.

Rules

  • One permanent code per agent: AGT- plus 6 characters, or an approved alias.
  • No discount for the user (UX C04).
  • An Apple restore never counts as a new sale.
  • Store fee, VAT, holds and earning currencies are settings; holds can be set per agent wallet.
  • Not in the original specification: added 25 Oct 2026.
